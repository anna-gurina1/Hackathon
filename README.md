# Hackathon

## Запуск через Docker

Нужен установленный Docker с поддержкой Compose. Из корня проекта выполните одну команду:

    docker compose up --build

Откройте <http://localhost:5000>. Чтобы открыть сайт с другого устройства в той же сети,
используйте IP-адрес компьютера, на котором запущен Docker, например `http://192.168.1.10:5000`.
Чтобы изменить порт, укажите `APP_PORT=8080` в `.env`.

Если в корне проекта есть `.env`, Compose передаст его настройки приложению (в том числе
ключи почты, AI и Cloudinary). Файл `.env` не включается в Docker-образ. Для production
задайте собственный `SECRET_KEY` в `.env`. SQLite-база и загрузки хранятся в постоянных Docker-томах;
`docker compose down` их сохраняет. Для остановки нажмите `Ctrl+C`, затем выполните
`docker compose down`. Не используйте `docker compose down -v`, если нужно сохранить данные.

1. У каждого своя часть работы. Стараемся не редактировать одновременно один файл чтобы не было конфликтов в гите.
2. Другим разработчикам отдаём максимум несколько главных функций.
3. Главные функции записываем в ARCHITECTURE.md: имя, вход, выход, пара слов о том что она делает 
4. Не меняем вход/выход общей функции молча. Если понадобилось изменить - сначала говорим команде.
5. ИИ может писать функции и помогать с проблемами, но основную архитектуру и общение между нашими частями придумываем сами
6. Если есть рабочий кусок кода: проверить, Commit, Push. Перед новой работой загрузить чужие обновления: Pull.

## Запуск и база данных

Первый запуск и после каждого `git pull`:

    pip install -r requirements.txt
    flask db upgrade
    python run.py

`flask db upgrade` создаёт базу с нуля или доводит старую `app.db` до актуальной схемы (данные остаются).
Один раз он заменил `migrate_db.py`, который удалён.

Если меняешь `database/models.py`:

    flask db migrate -m "что изменилось"
    flask db upgrade

Новый файл из `migrations/versions/` коммитим вместе с кодом, тогда у всех схема обновляется одной командой.

## Почта

- Регистрация: на почту уходит ссылка, аккаунт создаётся и вход происходит только после её открытия (ссылка живёт 24 часа).
- Вход и регистрация: на один адрес письмо можно отправить не чаще раза в минуту (`backend/throttle.py`).
- Письма уходят в фоне (отдельный поток), страница не ждёт Gmail. Ошибки отправки пишутся в лог сервера.
  `MAIL_BACKGROUND=0` в `.env` возвращает отправку «с ожиданием». Без `MAIL_SERVER` письма печатаются в консоль.
- Отправитель писем: по умолчанию адрес из `MAIL_USERNAME` с именем «Bitwise» (`MAIL_FROM_NAME`). `MAIL_FROM` задавайте, только если этот адрес действительно принадлежит почтовому серверу (например, ваш домен с настроенными SPF/DKIM) — иначе письма попадают в спам.
