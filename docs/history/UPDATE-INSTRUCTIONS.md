# Точечное обновление: личный режим, выбор кабинета и выравнивание

## Что исправлено

- В личном кабинете владелец видит свой опубликованный курс как ученик: начать, продолжить, пройти тест; без конструктора и удаления.
- Для приватного курса в личном режиме действуют те же правила, что для другого учащегося: одобрение заявки или приглашение. Описание по-прежнему видно в каталоге. Черновик не становится доступным ученикам.
- Управление курсами, командой, кандидатами и тарифом доступно только в выбранной компании с подходящей ролью. Старая открытая форма после смены кабинета не обходит эту проверку.
- Выбор кабинета сразу открывает его главную страницу. Кнопки «Переключить» при работающем JS нет. При отключённом JS доступна запасная кнопка отправки формы.
- На авторской карточке опубликованного курса есть «Пройти как ученик»: переход в личный режим с возвратом к этому курсу. Это не автоматическая запись и не обход приватного доступа.
- Ссылки уроков в авторском режиме открывают предпросмотр без результатов, а не закрытый ученический урок без Enrollment.
- Сообщения 403, 404 и 409 выровнены по общему контейнеру сайта. Заголовки, текст и действия больше не прижаты к краю экрана.

## Как поставить поверх последнего архива

Обновление основано на выданном ранее Bitwise-private-courses-fixed.zip, не на скачанной текущей ветке вашего GitHub. Ваши новые изменения я не вижу: перед заменой посмотрите diff. В точечном архиве нет run.py, core/config.py и backend/routes/site_auth.py — правки адреса сервера и входа в этих файлах не заменяются.

1. Остановите сервер. Сохраните свои изменения коммитом и сделайте резервную копию базы. Убедитесь через `git status`, что незакоммиченных правок нет.
2. Лучше работать в отдельной ветке от вашей актуальной версии, например:

   ```bash
   git switch -c fix/workspace-context-layout
   ```

3. Из точечного архива скопируйте **содержимое** папки `Bitwise-update` в корень проекта (рядом с run.py), сохраняя относительные пути. Не создавайте вложенный проект внутри проекта. Замените перечисленные в UPDATE-FILES.txt файлы, сравнив собственные правки. Все файлы обновления нужны вместе: серверные проверки и интерфейс связаны.
4. `.env`, базу, uploads, .git и виртуальное окружение не трогайте. В обновлении их нет. Новых runtime-зависимостей нет.
5. Если база уже на `0009`, **новая миграция для этой доработки не нужна**. Проверка:

   ```bash
   python -m flask --app run db current
   ```

   Если осталась более старая ревизия, сначала изучите START-HERE.md и выполните upgrade на копии базы. Полный архив содержит предыдущие миграции 0008/0009; точечный архив их не заменяет.
6. Запустите сервер:

   ```bash
   python run.py
   ```

7. В браузере сделайте жёсткое обновление страницы (`Ctrl+F5`), чтобы не остался прежний main.js/CSS. Если используете CDN или внешний кэш, обновите его по правилам хостинга.
8. Выберите «Личный кабинет», откройте свой опубликованный курс, начните и пройдите тест. Выберите компанию и убедитесь, что появились авторские действия; переключитесь обратно — они должны исчезнуть, а результат сохраниться.
9. Для проверки сетки откройте несуществующий адрес (404) и авторский адрес в личном режиме (403). Эти отказы остаются корректными; исправлена их вёрстка, а не отключена защита.

Если тестовые зависимости уже установлены:

```bash
python -m pytest -q
python translations/check.py
```

Проверенный результат: 70 passed, 614 текстов перевода, 0 проблем. Предупреждения datetime.utcnow() относятся к Flask-Login, не к падениям тестов.

После проверки сохраните изменения коммитом и отправьте ветку. Только затем объединяйте с основной веткой. Git не откатывает базу и локальные секреты.

## Если ошибка 403 при обучении осталась

Нужны путь страницы (например `/course/12/lesson/1`, не ссылка входа с токеном), выбранный кабинет и относящиеся к запросу строки терминала. Секреты, полный .env и одноразовые ссылки не присылайте. Снимок без адреса показывает отказ, но не доказывает его причину. Не удаляйте Enrollment, не отключайте авторизацию и не делайте базу заново.
