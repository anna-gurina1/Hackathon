# Запуск и безопасное обновление

## Если сайт уже работает в D:\Hackathon

Не удаляйте всю папку. Этот архив содержит код, но **не содержит вашу `.env`, `app.db`, `.git`, среду Python и загруженные файлы**.

1. Остановите запущенный сервер: `Ctrl+C` в его терминале.
2. Скопируйте **всю** текущую папку `D:\Hackathon` в `D:\Hackathon-backup`. Перед копированием база не должна изменяться работающим сервером. Если ваша база находится в другом месте, сохраните её отдельно.
3. Распакуйте новый архив в отдельную папку. Внутри находится папка `Hackathon`; сначала посмотрите `REFACTOR-CHANGED-FILES.txt` и `README.md`.
4. Для пробного запуска предпочтительно сделайте вторую копию своего проекта, например `D:\Hackathon-check`, и перенесите туда содержимое новой `Hackathon`. Заменять можно одноимённые **исходники** после резервной копии, но не удалять весь старый проект. Если после отправки архива команда ещё редактировала код, изменения нужно объединить, а не перезаписывать вслепую.
5. Убедитесь, что в копии остались ваша `.env`, копия базы и uploads. **DATABASE_URL не должен указывать на рабочую/production-базу.** При пустом DATABASE_URL используется `app.db` рядом с `run.py`; проверьте также переменные окружения терминала. Для локального теста задайте `APP_ENV=development`, `MAIL_SERVER=` и отключите настоящие внешние сервисы, если не планируете их вызывать. Переменные Brevo тоже могут включать отправку писем: очистите `BREVO_API_KEY` для полностью локальной проверки.
6. Не используйте скопированную `.venv`: создайте её заново в новой папке, как ниже. В текущей рабочей папке существующая исправная среда может остаться — runtime-зависимости в этом обновлении не менялись.
7. Откройте именно папку копии в VS Code и запустите сайт. Обновите страницу браузера с `Ctrl+F5`.

Новые миграции **не добавлены**. Если у вашей объединённой версии уже установлена ревизия `0010`, ради рефакторинга не нужно менять базу. Команда `python -m flask --app run db current` показывает её состояние. Если версия старее, миграции выполняйте только на резервной копии, после проверки.

### Что можно убрать из старой папки после переноса

- `frontend/static/js/tips.js`: каталог теперь использует `catalog.js` и `catalog-cards.js`; обновлённый шаблон подключает только новый модуль.
- `database/test_queries`: старый файл без `.py`, с ожиданиями от прежней модели компании. Рабочие актуальные проверки находятся в `tests/` и сохранены.
- `__pycache__/`, `*.pyc`, `.pytest_cache/`: автоматически создаваемые кэши. Удаление необязательно; Python создаст их снова. Не путайте их с кодом и данными.
- Старые корневые инструкции CHANGED-FILES, UPDATE-FILES, UPDATE-INSTRUCTIONS, UI-PLAN, CHANGES-AND-LIMITS, START-DESIGN, DESIGN-QA, DESIGN-CHANGED-FILES и DESIGN перенесены в `docs/history/` и `docs/DESIGN.md`. Если при наложении они остались в корне, их можно убрать: сначала убедитесь, что соответствующая копия есть в `docs/`. Для запуска нужен новый START-HERE.md.

Ничего автоматически удаляющего ваши данные в архиве нет. `migrations/`, `.env`, базу, `uploads/`, `.git/`, `tests/` удалять не нужно.

## Запуск в отдельной новой папке

Нужен Python 3.12+. В терминале **папки с `run.py`**:

```powershell
python -m venv .venv
```

Windows PowerShell — можно обходиться без активации, не меняя политику безопасности:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

Linux/macOS:

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
```

Если используете активированную среду, вместо полного пути далее достаточно `python`.

### Только для новой пустой конфигурации

Скопируйте `.env.example` в `.env`. **Не выполняйте копирование поверх своей существующей `.env`.** Создайте ключ и вставьте его локально в SECRET_KEY:

```powershell
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_hex(32))"
```

Для локального запуска: `APP_ENV=development`, пустые `DATABASE_URL`, `MAIL_SERVER`, `BREVO_API_KEY`; `PUBLIC_URL=http://127.0.0.1:5000`. Также проверьте переменные окружения терминала. Без почтового сервиса в режиме разработки ссылка входа печатается в вашем терминале. Никому её не пересылайте; этот режим не предназначен для публичного сервера. В `APP_ENV=production` такой вывод отключён: для отправки нужен настроенный почтовый транспорт.

Только для новой базы или проверенной копии старой:

```powershell
.\.venv\Scripts\python.exe -m flask --app run db upgrade
```

Запуск:

```powershell
.\.venv\Scripts\python.exe run.py
```

Откройте http://127.0.0.1:5000. Не используйте VS Code Live Server/Go Live: это Python-сайт с серверной логикой, а не набор самостоятельных HTML-файлов.

Для Linux/macOS замените `.\.venv\Scripts\python.exe` на `.venv/bin/python`.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe translations/check.py
```

Проверьте каталог, смену темы, вход, выбор кабинета, свой курс, обучение и предложения работы. Настоящие почту, видео/PDF в Cloudinary и AI нужно проверять отдельно со своей конфигурацией.

## Отдельная резервная копия SQLite

После установки зависимостей:

```powershell
.\.venv\Scripts\python.exe tools/backup_sqlite.py "D:\Hackathon\app.db" backups
```

Убедитесь, что файл копии появился. Для PostgreSQL нужны средства хостинга/pg_dump, а не этот инструмент. Миграции не удаляйте и не запускайте `db init` повторно для существующего проекта. Для отката нужны старая версия кода **и соответствующая резервная копия данных**; нельзя гарантировать безопасный откат просто заменой исходников после новых записей.

## Если работаете через Git

Сначала сохраните/согласуйте изменения команды, затем создайте отдельную ветку:

```bash
git status
git switch -c refactor/readability
```

После переноса проверьте diff, протестируйте сайт и покажите изменения команде. Не добавляйте в коммит `.env`, базы, резервные копии или ключи.
